Мотивация
Система мониторинга критически важна для «Александрита», так как позволит:
•	Контролировать растущую нагрузку на основные узлы системы
•	Предотвращать критические ситуации, контролируя ключевые метрики и состояние «железа»
•	Оптимизировать работу системы
•	Улучшить качество обслуживания клиентов
•	Сохранить бизнес-репутацию
•	Эффективно масштабировать бизнес
Внедрение мониторинга поможет компании не только решить текущие проблемы, но и создать прочную основу для дальнейшего роста и развития.

Выбор подхода к мониторингу
Для облачной инфраструктуры «Александрита» оптимальным является комбинация LTES + RED, так как:
•	Обеспечивает полный охват всех критически важных метрик
•	Учитывает особенности микросервисной архитектуры
•	Позволяет эффективно мониторить как пользовательский опыт, так и инфраструктуру
•	Хорошо интегрируется с облачными инструментами
•	Обеспечивает проактивное обнаружение проблем

Метрики
Сразу оговоримся, что состав метрик может меняться в процессе развития архитектуры ПО, но на текущий момент оптимально видится следующий набор метрик:
- Number of message in flight in RabbitMQ
Назначение: мониторинг количества сообщений в процессе обработки
Ярлыки:
environment
queue_name

- Number of dead-letter-exchange letters in RabbitMQ
Назначение: мониторинг количества недоставленных сообщений
Ярлыки:
environment
queue_name

- RPS для всех API (shop, CRM, MES)
Назначение: отслеживание нагрузки на все API
Ярлыки:
endpoint
response_code

- CPU %  и Memory Utilisation for MES API
Назначение: использование процессора и памяти для MES API сервиса, как наиболее узкого места и требующего большого объема вычислительных ресурсов
Ярлыки:
instance_id
environment 

- Size of shop и MES db 
Назначение: контроль за размером базы данных приложений
Ярлыки:
instance_id
environment 

- Number of HTTP 500 для всех API
Назначение: отслеживание критических ошибок
Ярлыки:
endpoint
error_type
timestamp
